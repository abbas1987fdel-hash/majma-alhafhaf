# مجمع الهفهاف

تطبيق ويب عربي لإدارة الزبائن والمخزون والديون والتسديدات.

## قاعدة البيانات والنشر

- المالك: `abbas1987fdel-hash`، فريق Convex: `bs-fdl`، المشروع: `majma-alhafhaf`.
- Production: `industrious-walrus-342`. عنوان العميل محفوظ في `deployment.json` وهو إعداد عام وليس مفتاحًا سريًا.
- `npm run build:pages` يثبّت عنوان Production حتى لو كانت `.env.local` تشير إلى Development.
- الرابط: https://abbas1987fdel-hash.github.io/majma-alhafhaf/
- GitHub Pages ينشر الواجهة فقط. تغييرات الخادم تُنشر منفصلة بواسطة `npx convex deploy` بعد التحقق من الفريق ووسم Production.

## التشغيل والفحص

```sh
npm ci
npm test
npx vitest run --config tests/backend.test.config.mjs
npx tsc --noEmit
npx oxlint app lib/ledger.ts lib/preferences.ts convex tests/backend.test.mjs vite.pages.config.ts
npm run build:pages
npm run preview:pages
```

للتطوير، هيئ Convex Development في `.env.local` ثم شغّل `npx vite --config vite.pages.config.ts --mode development`.

## الحفظ والدخول

تُحفظ البيانات الأساسية والإعدادات والرمز في Convex. بعد أول دخول متصل يحفظ التطبيق نسخة مشفّرة في IndexedDB على الجهاز، مع قائمة تعديلات دائمة للمزامنة. لا يستخدم التطبيق LocalStorage. ملفات التشغيل فقط محفوظة في Cache Storage لتشغيل التطبيق المثبت دون شبكة، ولا تُخزّن استجابات قاعدة البيانات فيه. يطلب الرمز عند كل فتح جديد. لا تُرسل أي رسالة واتساب تلقائيًا.

كل قراءة وكتابة للحسابات تتطلب جلسة يتحقق منها الخادم. الرمز يُشتق عبر scrypt بملح عشوائي، والجلسات عشوائية ومحدودة باثنتي عشرة ساعة. تغيير الرمز يبطل الجلسات السابقة. تُحد محاولات التخمين. لا يوجد رمز افتراضي أو تلميح داخل حزمة الواجهة.

تهيئة الرمز الأولى تتم بمتغير خادم خاص `INITIAL_PIN` وتشغيل الدالة الداخلية `auth:bootstrap`، ثم حذف المتغير. التهيئة لا تستبدل إعدادات موجودة. لا تحفظ الرمز أو مفاتيح النشر في Git.

يتحقق الخادم من المبالغ وترتيب الدين والتسديد ومنع تجاوز الرصيد. إصدارات السجلات تمنع الكتابة فوق تعديل متزامن دون تنبيه. الشعار يُرفع عبر رابط جلسة محدود الاستخدام والحجم. `APP_ORIGIN` يحدد أصل موقع الإنتاج، و`DEV_APP_ORIGIN` مخصص لبيئة التطوير فقط.

## المتابعة

يستخدم المشروع Sentry الحالي `majma-alhabhab` دون إنشاء مشروع مكرر. DSN في إعدادات البيئة وGitHub Secret فقط. لا تجمع المتابعة بيانات الزبائن أو محتوى المعاملات أو رموز الدخول.

الفحص الشامل للقالب يحتوي 19 خطأ قديمًا في مكونات غير مستخدمة؛ فحص ملفات التطبيق والخادم المعدّلة مستقل وناجح. التثبيت يحتاج متصفحًا يدعم تطبيقات الويب؛ اسم وأيقونة التطبيق المثبت يأتيان من manifest، وتخص إعدادات الهوية الواجهة ورسائل المشاركة.

## تحديث الأوفلاين والمخزون

- زر مشاركة الدين الكلي يفتح محادثة رقم الزبون مباشرة برسالة تشمل الاسم والرصيد والتاريخ والوقت بتوقيت بغداد.
- المخزون يتطلب كلمة سر مستقلة. قراءته وتعديل مواده محميان على الخادم؛ تغيير كلمة السر يبطل تصاريح المخزون القديمة.
- قبل نشر الواجهة المعدلة، يلزم نشر وظائف Convex إلى Production بعد الإذن فقط، وتعيين `INITIAL_INVENTORY_PASSWORD` من الملف المحلي المستثنى `.env.inventory-bootstrap`، وتشغيل `auth:bootstrapInventory` الداخلي مرة واحدة ثم إزالة المتغير. التهيئة لا تستبدل كلمة سر موجودة.
- لا تُشغّل أوامر deploy/dev/bootstrap على أي قاعدة سحابية أثناء فترة انتظار الإذن. لا تستخدم نسخة الواجهة المعدلة مع الخادم القديم للمعاينة؛ فحص الواجهة المحلي في `outputs/preview.html` يستخدم بيانات وهمية ولا يتصل بقاعدة حقيقية.

## الأوفلاين والتشغيل المثبت

- افتح التطبيق وسجّل الدخول بالإنترنت مرة أولى على كل جهاز. افتح المخزون بكلمته مرة متصلًا أيضًا. بعدها يمكن عرض وإضافة وتعديل الزبائن والديون والتسديدات والمواد دون شبكة.
- الحسابات والمخزون لهما خزنتان مستقلتان مشفرتان بـAES-GCM، بمفتاح مشتق من كلمة القسم بـPBKDF2 وملح عشوائي. لا تحفظ كلمات المرور صراحة. قفل التطبيق يزيل المفاتيح من حالة الواجهة؛ تعديل رمز من جهاز آخر لا يمكن أن يمحو نسخة جهاز غير متصل عن بُعد.
- لا يظهر التعديل محفوظًا حتى يكتمل تخزينه محليًا. يعرض التطبيق عدد التعديلات المنتظرة ويزامنها عند عودة الشبكة. مزامنة المخزون تتطلب فتحه. بعد إعادة التشغيل تُعرض رسالة للتحقق من مخزونه المقفل بدل الادعاء أن كل البيانات متزامنة.
- كل عملية لها معرّف دائم وإيصال خادم ذري في `operationReceipts` لمنع تكرارها بعد انقطاع الرد. يحتفظ الخادم بفحص الإصدارات وبقواعد التسديد. يتوقف الإرسال عند تعارض ولا يستبدل التعديلات بصمت. يمكن تنزيل نسخة للمراجعة؛ اعتماد بيانات الخادم يتطلب تأكيدًا ويُمنع أثناء أي إرسال غير محسوم.
- تسجيل الدخول وتغيير الرموز والإعدادات ورفع الشعار تتطلب الإنترنت، عدا فتح نسخة سبق تجهيزها. عند انتهاء الجلسة تظهر إعادة الاتصال مع إبقاء التعديلات. إذا تغير الرمز من جهاز آخر، افتح النسخة المحفوظة بالرمز القديم من شاشة الخطأ ثم أدخل الجديد في نموذج المزامنة؛ لا تمسح التخزين لاستعادة الدخول.
- نافذة واحدة تملك حق الكتابة على نسخة الجهاز عبر Web Locks. يجب قفل التطبيق في النافذة الأولى قبل فتحه في أخرى.
- لا تمسح بيانات المتصفح أو تزلها قبل اكتمال المزامنة. التخزين المحلي ليس بديلًا لنسخة الخادم، ونقص المساحة يظهر فشلًا صريحًا. يسمح التطبيق بطلب التخزين الدائم إن دعمه المتصفح.
- يبني Vite قائمة ملفات التشغيل كاملة مع إصدار محتوى؛ تنزيل غير مكتمل لا يفعّل تحديث العامل. شاشة HTML أولية وحدّ أخطاء React يعرضان رسالة وإعادة محاولة بدل شاشة فارغة. تحتفظ الواجهة بملفات النسخ السابقة للتوافق مع الصفحات المفتوحة.
- يجب نشر مخطط وإيصالات المزامنة ووظائف المخزون إلى **Production** قبل نشر هذه الواجهة، بعد إذن المستخدم فقط. لا تنشر الواجهة وحدها.

### أدلة الفحص المحلي

```sh
npm test
node --test tests/offline-shell.test.mjs
npx vitest run --config tests/backend.test.config.mjs
npx tsc --noEmit
npm run build:pages
```

تشمل الاختبارات فقدان الرد وإعادة التشغيل وإعادة الإرسال للخادم الحقيقي داخل `convex-test`، منع التكرار، تعارض الإصدارات، خطأ التخزين وإعادة تشفير الرمز. المعاينة المعزولة `outputs/offline-preview.config.mjs` تستخدم الواجهة وIndexedDB والعامل الحقيقيين مع بديل Convex تجريبي فقط. تم اختبار فصل الشبكة وفتح `?app=1`، دين 2000 وتسديد 500، تعديل المخزون، إعادة الفتح أوفلاين، ثم المزامنة. اختبار التثبيت على جهاز المستخدم يبقى منفصلًا عن اختبارات المعاينة؛ يتطلب التشغيل الأول اتصالًا لتنزيل النسخة وتجهيز بيانات الجهاز.
